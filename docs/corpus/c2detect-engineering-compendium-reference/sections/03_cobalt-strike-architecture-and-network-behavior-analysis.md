The Beacon client generates a public/private key pair, with the private key used to encrypt messages sent to the C2 server and the public key used for decryption. This handshake process not only ensures that both parties are legitimate but also allows for the establishment of a shared secret key used for symmetric encryption. The use of both asymmetric and symmetric encryption in the Beacon protocol provides a layered security approach, making it more difficult for adversaries to intercept or manipulate communications without detection.

Another evasion technique employed by the Beacon protocol is the use of domain fronting. In summary, the Cobalt Strike Beacon communication protocol is a robust and sophisticated mechanism that enables persistent, encrypted, and stealthy communication between the Beacon client and the C2 server.
